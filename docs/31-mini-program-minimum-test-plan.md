# Tree 小程序最小可行测试计划

## 1. 测试目标

本计划用于个人开发者在上传体验版前，以最小人力验证小程序核心流程是否闭环。

重点不是做大规模用户研究，而是排除以下翻车点：

- 用户是否能创建家庭并开始搭建家庭树。
- 成员、家庭树、邀请、绑定、暂存、接入流程是否顺畅。
- 不同账号登录后，家庭树称谓和视角是否符合预期。
- 微信分享邀请链路是否真实可用。
- 家庭解散、冷静期、恢复等高风险流程是否闭环。

## 2. 最小测试规模

### 2.1 最低规模

最低可行配置：

- 测试人员：1 名开发者 + 1 名真实微信好友。
- 测试账号：至少 3 个小程序账号。

账号角色：

| 账号 | 角色 | 用途 |
| --- | --- | --- |
| A | 创建者 | 创建家庭、添加成员、发起邀请、管理家庭 |
| B | 被邀请绑定节点的成员 | 接受“绑定指定成员节点”的邀请 |
| C | 只加入家庭但暂不绑定节点的成员 | 接受“加入家庭但身份待确认”的邀请 |
| 好友账号 | 真实外部体验者 | 验证微信分享、邀请页理解成本、接受路径 |

说明：

- A/B/C 可以由开发者使用不同微信账号或测试账号完成。
- 好友只需参与邀请链路，不需要完整测试所有管理功能。
- 不建议一开始超过 5 人，避免反馈过散。

### 2.2 稳妥规模

如果条件允许，建议：

- 开发者自测 3 个账号。
- 真实好友 1–2 人。
- 总计 4–5 个真实使用身份。

## 3. 测试环境

### 3.1 小程序环境

- 使用微信开发者工具或体验版。
- 推荐最终以体验版真机为准。
- 测试前确认体验版连接的是 staging API。

### 3.2 后台环境

需要能访问 admin 后台，用于：

- 审核公开展示申请。
- 审核家庭解散申请。
- 查看账号权益配置。
- 查看家庭状态、操作记录、解散状态。

### 3.3 数据准备

建议新建一个专门测试家庭，避免污染真实数据。

基础结构建议：

- 创建者本人。
- 父亲、母亲。
- 配偶。
- 子女。
- 兄弟姐妹。
- 父亲的兄弟姐妹。
- 至少 1 个暂存成员。
- 至少 1 个待邀请绑定节点。
- 至少 1 个只加入家庭但暂不绑定节点的邀请。

## 4. 测试范围

### 4.1 必测流程

| 编号 | 流程 | 目标 |
| --- | --- | --- |
| P0-1 | 创建家庭 | 验证创建资格、资料校验、创建后引导 |
| P0-2 | 添加亲属 | 验证父母、配偶、子女、兄弟姐妹添加 |
| P0-3 | 暂存成员 | 验证“知道姓名但关系不确定”的场景 |
| P0-4 | 暂存成员接入家庭树 | 验证后续确认分支后可接入 |
| P0-5 | 邀请绑定节点 | 验证指定成员节点邀请、好友接受、绑定成功 |
| P0-6 | 邀请加入家庭但不绑定节点 | 验证身份待确认邀请不提前生成成员节点 |
| P0-7 | 视角切换与称谓 | 验证不同成员视角下称谓正确 |
| P0-8 | 成员编辑与删除 | 验证姓名、性别、健在状态、删除失败提示 |
| P0-9 | 关系调整 | 验证删除/调整关系后家庭树同步 |
| P0-10 | 解散/冷静期/恢复 | 验证高风险流程闭环 |

### 4.2 可选流程

| 编号 | 流程 | 目标 |
| --- | --- | --- |
| P1-1 | 公开展示申请 | 验证申请、审核、开启展示、关闭展示 |
| P1-2 | 阅读新手教程 | 验证文章入口和图文说明是否能帮助用户 |
| P1-3 | 账号与安全 | 验证资料、备用登录、注销入口文案 |
| P1-4 | 家庭事务 | 验证收到邀请、提交申请、取消申请列表 |

## 5. 详细测试流程

### 5.1 创建家庭与初始引导

测试账号：A

步骤：

1. 进入小程序。
2. 登录并完善资料。
3. 点击创建家庭。
4. 填写姓氏、性别、家庭名称、地区、简介。
5. 创建成功后进入家庭详情。
6. 检查是否出现“添加父母 / 添加配偶 / 添加子女”等初始引导。
7. 点击其中一个快捷入口，确认进入添加成员流程。

通过标准：

- 创建前如果无创建资格，应在进入表单前提示。
- 创建成功后用户知道下一步该做什么。
- 快捷入口进入的添加流程对象正确。

### 5.2 添加家庭树节点

测试账号：A

步骤：

1. 从家庭详情进入家庭树。
2. 点击添加成员。
3. 选择“从谁开始”。
4. 分别添加父亲、母亲、配偶、子女。
5. 添加成功后，检查是否提示“继续添加 TA 的亲属”。
6. 点击继续添加，确认表单起点切换到刚创建的成员。

通过标准：

- 家庭树刷新后出现新节点。
- 称谓显示合理。
- 添加成功后的下一步提示不阻断流程。
- 父亲/母亲/配偶重复添加时，后端拒绝提示能被用户看到。

### 5.3 添加兄弟姐妹

测试账号：A

步骤：

1. 选择已有成员。
2. 添加兄弟姐妹。
3. 若该成员没有父母节点，确认系统提示需要先创建父母。
4. 先添加父母后，再添加兄弟姐妹。

通过标准：

- 数据库不产生 `SIBLING` 关系。
- 兄弟姐妹通过共享父母关系展示。
- 错误提示用户能看懂。

### 5.4 暂存成员与接入家庭树

测试账号：A

步骤：

1. 进入添加与调整页面。
2. 选择“添加暂存”。
3. 输入成员姓名、性别、健在状态。
4. 保存暂存成员。
5. 检查是否提示“去接入”。
6. 进入“接入暂存”。
7. 选择待接入成员、起点成员和关系。
8. 接入后返回家庭树检查节点位置。

通过标准：

- 暂存成员不会出现在主关系图中。
- 暂存成员会出现在未定位成员或待接入列表中。
- 接入后进入家庭树。
- 接入后称谓重新计算。

### 5.5 邀请绑定指定节点

测试账号：A 发起；B 接受。

步骤：

1. A 在家庭树中点击一个未绑定成员节点。
2. 选择邀请本人绑定。
3. 生成节点邀请。
4. 通过微信发送给 B。
5. B 打开邀请页面。
6. B 检查家庭名称、目标成员、邀请说明。
7. B 接受邀请。
8. B 进入我的家庭。
9. B 打开家庭树，检查当前视角是否为 B 绑定的节点。

通过标准：

- 邀请页只显示节点绑定邀请，不应同时显示家庭邀请表单。
- 目标节点姓名不能乱码。
- B 接受后绑定到指定成员节点。
- A 的家庭树节点显示已绑定或不再显示邀请入口。
- 邀请未接受前，节点显示“邀请中”。

### 5.6 邀请加入家庭但暂不绑定节点

测试账号：A 发起；C 接受。

步骤：

1. A 进入家庭事务或发出的家庭邀请。
2. 选择邀请加入家庭。
3. 填写身份待确认标签。
4. 生成家庭邀请。
5. C 通过微信打开邀请。
6. C 接受邀请。
7. C 进入我的家庭查看该家庭。
8. A 回到家庭树和成员表检查是否没有提前生成未定位成员。
9. 后续由 A 根据身份确认情况再添加暂存成员或接入家庭树。

通过标准：

- 邀请未确认前不生成未定位成员。
- 接受邀请后 C 属于该家庭。
- C 不会被错误绑定到某个节点。
- 身份标签能帮助 A 区分多个待确认邀请。

### 5.7 视角切换与称谓

测试账号：A，必要时 B/C。

步骤：

1. 在家庭树中切换到创建者视角。
2. 截图记录称谓。
3. 切换到父亲、母亲、配偶、子女、兄弟姐妹、堂亲分支成员视角。
4. 检查称谓变化。
5. 使用 B 登录，确认 B 看到的称谓与手动切换到 B 节点一致。

重点检查：

- 配偶视角是否与其绑定成员视角一致。
- 堂哥堂姐的配偶是否显示合理。
- 祖辈兄弟姐妹及其后代是否显示合理。
- 无法覆盖的关系是否退化为可理解的关系路径，而不是空白。

通过标准：

- 手动切换视角与对应账号登录视角一致。
- 主要亲属称谓不明显错误。
- 不支持称谓时不出现空白或乱码。

### 5.8 成员编辑、健在状态与删除

测试账号：A

步骤：

1. 编辑一个成员姓名。
2. 返回家庭树，确认节点名称立即更新。
3. 标记成员已故。
4. 再标记健在。
5. 删除无子女、非创建者、非管理员成员。
6. 尝试删除有子女成员。
7. 尝试删除创建者或管理员绑定成员。

通过标准：

- 编辑后家庭树和成员表同步。
- 健在/已故快捷操作按当前状态显示。
- 可删除成员能删除。
- 不可删除成员失败原因对用户可见。

### 5.9 关系调整

测试账号：A

步骤：

1. 选择一个成员进入关系调整。
2. 删除一条错误配偶关系。
3. 删除一条错误父母子女关系。
4. 调整父母子女关系性质。
5. 返回家庭树检查位置和称谓。

通过标准：

- 删除或调整关系后家庭树立即刷新。
- 称谓随关系变化重新计算。
- 高风险操作有确认提示。

### 5.10 解散申请、冷静期与恢复

测试账号：A；后台管理员。

步骤：

1. A 在家庭设置中提交解散申请。
2. A 返回家庭详情，确认可看到撤销入口。
3. 后台审核通过。
4. A 打开我的家庭，确认该家庭标记为冷静期。
5. A 进入家庭详情。
6. 测试恢复家庭。
7. 再次提交解散申请并审核通过。
8. 测试跳过冷静期完成解散。
9. 后台确认状态同步。

通过标准：

- 待审核时可撤销。
- 冷静期内可查看、不可编辑。
- 创建者可恢复。
- 创建者可跳过冷静期完成解散。
- admin 后台状态与小程序一致。

## 6. 好友测试脚本

给真实好友的测试任务尽量简单，不超过 5 分钟。

建议文案：

> 我发你一个 Tree 小程序家庭邀请链接。你帮我看一下：
>
> 1. 点开后是否知道是谁邀请你。
> 2. 是否看得懂你要确认的家庭或成员身份。
> 3. 接受邀请前有没有担心的地方。
> 4. 接受后能不能找到“我的家庭”。
> 5. 哪一步你觉得不清楚，直接截图发我。

好友只需反馈：

- 看不懂哪里。
- 是否敢点接受。
- 接受后是否知道下一步。
- 有没有报错或打不开。

## 7. 问题记录模板

每个问题建议按以下格式记录：

```text
问题编号：
测试账号：
测试环境：开发者工具 / 真机体验版
页面：
操作步骤：
期望结果：
实际结果：
截图：
是否阻塞体验版：是 / 否
优先级：P0 / P1 / P2
备注：
```

优先级定义：

- P0：流程无法继续、数据错误、权限错误、称谓明显错误、分享不可用。
- P1：流程能继续但用户容易误解、入口不清、提示不够。
- P2：文案、样式、轻微交互优化。

## 8. 体验版前通过标准

体验版上传前，至少满足：

- 创建家庭主流程通过。
- 添加成员和家庭树显示通过。
- 指定节点邀请绑定通过。
- 加入家庭但暂不绑定节点通过。
- 暂存成员接入通过。
- 视角切换主要称谓通过。
- 删除失败原因能被用户看到。
- 解散冷静期状态在小程序和 admin 后台一致。
- 无小程序启动报错。
- 无明显乱码、空白页面、按钮无响应。

## 9. 不在本轮测试范围

以下内容不作为最小测试必须项：

- 大规模并发。
- 多家庭复杂权益组合。
- 大量成员家庭树性能极限。
- 完整用户访谈。
- 公开展示 SEO 或 PC Web 体验。
- 后台复杂运营流程。

## 10. 建议执行顺序

1. 开发者使用 A 账号完整创建家庭。
2. 开发者用 A 账号添加 8–12 个典型成员。
3. 开发者用 A 账号验证视角切换和称谓。
4. 开发者用 B 账号验证节点绑定邀请。
5. 开发者用 C 账号验证只加入家庭邀请。
6. 找 1 个真实好友验证微信分享体验。
7. 测解散、冷静期、恢复、后台状态同步。
8. 记录 P0/P1 问题。
9. 修完 P0 后再上传体验版或扩大测试范围。
